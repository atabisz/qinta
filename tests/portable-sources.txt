# Every src/ file that a non-Windows build compiles, one per line.
#
# WHY THIS FILE EXISTS
#
# scripts/probe-portable-linux.sh used to assert a hand-picked handful of objects
# by name. That is an under-reporting instrument, and it cost a real mistake on
# 2026-09-10: it named five objects, so the portable core looked like ~2,800 lines
# when the Linux build was in fact already compiling 16,252. The conclusion drawn
# from the smaller figure -- that ~13,900 lines had never been read by GCC and
# needed wiring up -- was wrong, and the work it implied was already done.
#
# So the probe no longer trusts a list of things to look for. It reads the set of
# source objects the build actually produced and compares it against this file in
# BOTH directions:
#
#   - a file here that was NOT compiled  -> something dropped out of a portable
#     target, or a target stopped building. Silent regression, now loud.
#   - a file compiled that is NOT here   -> the portable surface grew without
#     anyone saying so. Add it deliberately, with a look at whether it belongs.
#
# That symmetry is the point. A one-directional check can only catch shrinkage,
# and it was growth this file's absence hid.
#
# Adding a line is a claim that a non-Windows compiler accepts the file. Do not
# add one to make the probe green -- run the probe and let it tell you.
#
# Windows-only files must NEVER appear here. scripts/probe-portable-linux.sh
# separately asserts that main_d2d.cpp, settings_app.cpp and settings_win32.cpp
# were not compiled at all.
#
# Files under tests/ must never appear here either, even when a non-Windows build
# compiles them. Every name below is read as src/<name> when the probe counts the
# portable share, so a tests/ entry would name a file that does not exist and
# silently spoil the figure. tests/render_api_shared.cpp made that mistake
# available: it is compiled off Windows and does not end in _tests.cpp, so the
# probe reported it UNEXPECTED and adding a line here looked like the fix. The
# actual fix was in the probe's filter, which now keys on the source directory
# instead of guessing from the filename. Those test objects are asserted by name
# further down that script.

# --- The platform seam and its consumers -------------------------------------
config_dir.cpp
platform_paths_posix.cpp

# --- The Qt rendering backend -------------------------------------------------
#
# This line does more than record a file. The Qt targets in CMakeLists.txt are
# opt-in (`find_package(Qt6 QUIET)`), because Windows has no Qt and must still
# configure -- and the previous commit noted the cost of that honestly: an opt-in
# target's ABSENCE is silent, so uninstalling Qt would leave the probe green with
# one fewer test.
#
# Listing render_qt.cpp closes that hole without giving up the opt-in, because the
# manifest is compared in both directions: if Qt goes missing off Windows, this
# file is listed-but-not-compiled and the probe fails MISSING rather than passing
# quietly. Qt is a hard requirement for the non-Windows build from here on, which
# is the correct reading of it being the chosen framework.
render_qt.cpp

# The Qt side of the TEXT seam, listed for the same reason and with the same
# consequence. Its Direct2D counterpart, src/text_d2d.cpp, must never appear here:
# it includes <dwrite.h> and is Windows-only by design, exactly like
# src/render_d2d.cpp.
text_qt.cpp

# --- Compiled off Windows, but NOT linked or run ------------------------------
#
# THREE ENTRIES. selection.cpp used to head this section and has moved
# to its own heading below: it is now linked and RUN off Windows by
# selection_tests. The blocker that kept it here -- App holding the Direct2D
# backend wrappers BY VALUE, so linking anything that instantiates an App wanted
# vtables out of the two Windows-only backend sources -- was removed by moving
# App's storage to pointers to the abstract seam types. The measurement, including
# the undefined symbols that actually appeared -- four, then a fifth, then md_parse,
# each found by a link rather than predicted -- and the check that the binary
# contains zero D2D wrapper symbols, is in the selection_tests comment in
# CMakeLists.txt.
#
# editrail.cpp is here because the build compiles it (the portable_compile_only
# OBJECT library in CMakeLists.txt), which is exactly what every other line here
# claims and no more. It reached zero errors when its two CRT calls (swprintf_s,
# _countof) moved to portable_str.h and std::size, and it compiles with include/
# and md4c only, no Qt at all -- measured, not assumed. Nothing executes it on
# EITHER platform; its drawing code goes through the render and text seams, which
# ARE asserted against each other, so the layer beneath it is tested and its own
# logic is not.
#
# READ THE COUNT OF THIS SECTION, NOT THE COUNT OF THE FILE. Every other line in
# this manifest is compiled AND linked AND run, so a reader totalling the lines
# and calling them tested files will be wrong by exactly the number of entries
# below. That is why it sits under its own heading instead of being sprinkled into
# the sections above.
editrail.cpp

# The two that are left of the three that arrived together, found by a census rather
# than by porting work: g++ -fsyntax-only over every file NOT listed in this
# manifest, which turned up six at zero errors. Two of the six had passing tests
# gated to Windows and are now in tested sections below; one is staying out
# deliberately (src/settings_app.cpp says why in its own header); these had nowhere
# to record the reading.
#
# syntax.cpp HAS LEFT THIS SECTION -- see its own heading below. This section's note
# used to say it was "the one that most deserves to leave", and that is now done
# rather than pending, which is the only reason a line moves out of here.
#
# search.cpp compiles but cannot link: it includes render.h and reaches into the
# layout, and src/render.cpp is 128 Direct2D/DirectWrite mentions deep, so a running
# target for it is a long way off.
#
# i18n_app.cpp is one function. It was split off i18n.cpp so that 1500 lines of
# string data could compile off Windows, and the half left behind turned out to
# compile too once App stopped naming a backend.
i18n_app.cpp
search.cpp

# --- The highlighter, compiled AND run off Windows -----------------------------
#
# syntax.cpp. 392 lines of pure logic -- ten keyword sets, a language-id lookup, a
# hand-written lexer and a colour switch -- and until tests/syntax_tests.cpp it had
# no test on EITHER platform. Its own header describes fixing 9 errors that only a
# non-Windows compiler surfaced, so it was MADE portable and then parked where
# nothing would notice if it stopped being correct. Compiling is not testing, and
# this line now claims both.
#
# The target needs NOTHING else on its link line: no md4c, no platform paths, no
# themes.cpp. It uses D2DTheme and SyntaxTokenType as types, not as behaviour, so
# the file has no undefined symbols outside the CRT -- measured by linking it, not
# predicted, because the equivalent prediction for selection.cpp was wrong three
# times running.
syntax.cpp

# --- The first file that takes an App& and is asserted off Windows -------------
#
# selection.cpp. Compiled, linked AND run by selection_tests on both platforms,
# so it belongs in a tested section rather than the compile-only one above.
#
# Its word-selection rules -- including the deliberate trailing-hit rule, where a
# caret just past a word selects the word rather than the space -- had never been
# executed by any test on any platform before that target existed.
#
# NOW ASSERTED IN FULL, by a second target. This section used to end by naming four
# functions it did not cover -- selectionOffsetAtPoint, selectionHighlightRects,
# selectionRangeRect and the populated path through selectionLineRange -- because
# they read app.layoutTextRuns, app.textRects and app.lineBuckets and so need a
# layout rather than a string. tests/app_fixture.h is that layout, and
# tests/selection_layout_tests.cpp asserts all four off Windows.
#
# The fixture works because LayoutTextRun::layout is a shared_ptr to the ABSTRACT
# tinta::TextLayout, so a fake layout is a class in a test header instead of a
# device, a factory and a window. It reaches branches a real backend cannot easily
# be made to reach: the caret-pair fallback in selectionHighlightRects, for one,
# which had never executed and turns out to agree with the primary path exactly.
selection.cpp

# --- Two files whose tests already existed and were gated to Windows anyway ----
#
# Neither needed a line changed. context_menu_tests and inline_style_tests sat inside
# `if(WIN32)` because they linked src/render_d2d.cpp and src/text_d2d.cpp, and their
# comments said why: App held the backend wrappers BY VALUE, so any target that
# instantiated an App wanted those vtables. That stopped being true when App's
# storage moved to pointers to the abstract seam -- the same unlock selection.cpp
# got -- and the comment was updated on selection_tests and left standing on four
# other targets. Nothing failed. The gate kept working, the tests kept passing on
# Windows, and the number of tests running off Windows was just lower than it had to
# be. A stale reason for a gate is silent in a way a stale reason in code is not.
#
# Measured before being written: both link and RUN off Windows with the two backend
# sources dropped, zero undefined symbols, zero FAIL lines.
context_menu.cpp
inline_style.cpp
