# tests/test-platforms.txt -- the platform reach of every ctest test, one row per test name.
#
# Columns: <test name> <platform> <reason>
#   platform is one of: both | windows-only | linux-only
#   reason is REQUIRED on every row that is not `both`, and its first token is a KIND:
#     sources:  the target compiles at least one src/*.cpp outside tests/portable-sources.txt
#               (the ${PLATFORM_PATHS_SOURCE} slot excluded -- that one is selected, not a blocker)
#     subject:  every source is portable; the TEST ITSELF is about a platform-only behaviour
#
# WHY THIS FILE EXISTS. README bases D and E are figures about two hosts, and for several passes they
# were the only rows of the gated table that nothing checked -- they read 30/35 and 30/39 while the
# suite grew from 39 targets to 50. Re-deriving them by hand then produced a false finding that
# reached pushed history: seven targets called "cheap wins, stranded for want of a CMakeLists entry",
# when five of them compile the entire Windows stack through ${INPUT_TEST_SOURCES} and one is
# Windows-only by subject. The derivation had matched _d2d/_win32 FILENAMES in add_executable lines
# and was blind to the same dependency arriving through a variable.
#
# So the reason column is not documentation -- it is gated, in both directions:
#   scripts/check-readme-figures.sh  asserts every `sources:` row's STATED COUNT EQUALS the measured
#                                    one -- not `>= 1`, which is what this line said until 2026-09-21
#                                    and is a weaker claim than the gate makes. The twelve README
#                                    `blockers:` figures are read out of this column, so a `>= 1`
#                                    census would let a row say 99 for a target compiling 17 and be
#                                    green at both ends. It also asserts every
#                                    `subject:` row has exactly ZERO, and that this file's
#                                    both+windows-only set equals the generated Windows ctest list.
#                                    Its census reads build-win-split/*.vcxproj -- CMake's own
#                                    generated project files, with every variable expanded, because
#                                    three separate static parses of CMakeLists.txt misled me in one
#                                    hour. Where no .vcxproj exists the claim SKIPS and says so.
#   scripts/probe-portable-linux.sh  asserts this file's both+linux-only set equals what a fresh
#                                    non-Windows configure actually produces, both directions.
#
# A `windows-only` row is a statement that work is owed, not that the target is finished. None of the
# twelve below is a CMakeLists entry away from moving: they are owed the Direct2D rasteriser's removal,
# or nothing at all because their subject has no non-Windows meaning.
#
# 17 -> 16 ON 2026-09-24: src/settings_app.cpp, which ${INPUT_TEST_SOURCES} links, joined
# tests/portable-sources.txt. No Win32 arm was extracted, so unlike the paragraph below it is a real
# fall of one; the five targets still need the Direct2D rasteriser's removal to move.
#
# THE input.cpp PORT LANDED 2026-09-21 AND MOVED NO ROW, which is worth stating because the opposite
# was the stated expectation. The five ${INPUT_TEST_SOURCES} rows read `sources: 17` before that port
# and `sources: 17` after it: src/input.cpp entered tests/portable-sources.txt and src/zen_mode_win32.cpp
# -- the Win32 arm the port extracted -- entered ${SOURCES} on the same commit, and by that manifest's
# own must-never-appear rule it can never be listed, because it calls SetWindowLongW, SetWindowPos,
# GetWindowPlacement, SetWindowPlacement and MonitorFromWindow. One file left the non-portable set and
# one joined it, so the census measured 17 both times. Extracting a Win32 arm is arithmetically
# NET-ZERO on a blocker count; the gain is the ratio inside the file, 4,553 portable lines for ~90
# non-portable ones, and this column cannot see that. Do not read an unchanged 17 as unchanged work --
# and note the enumeration after `--` names FOUR of the seventeen and is NOT gated, so it is the part
# of this row that can rot while the number stays green. It did: it led with input.cpp for one commit
# too long.
#
# 17 → 18 ON 2026-09-23, AND THAT IS NOT MORE WORK OWED. src/tab_tearoff_win32.cpp is tabs.cpp's
# tear-off arm, extracted so tabs.cpp compiles off Windows (errors 40 → 0). But tabs.cpp stayed OFF the
# manifest for one commit, so nothing left the set and one file joined it.
#
# 18 → 17 THE SAME DAY, WHEN THE DONOR LEFT, AND THE REASON IT HAD STAYED WAS WRONG. The sentence here
# read "compiling is not linking, and its callees still have no Qt arm". Both halves are true and
# neither is the manifest's test: an entry claims only that the file compiles off Windows, and
# input.cpp is an entry that links into nothing. So tabs.cpp joined the compile-only section, and the
# net-zero rule above finally balances: tab_tearoff_win32.cpp in, tabs.cpp out, 17 again. The gain is
# the same kind as input.cpp's and just as invisible here: 1,622 lines compile off Windows for 66 that
# do not.
