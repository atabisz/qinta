# Every src/ file that a non-Windows build compiles, one per line.
#
# WHY THIS FILE EXISTS
#
# scripts/probe-portable-linux.sh used to assert a hand-picked handful of objects
# by name. That is an under-reporting instrument, and it cost a real mistake on
# 2026-09-10: it named five objects, so the portable core looked like ~2,800 lines
# when the Linux build was in fact already compiling 16,252. The conclusion drawn
# from the smaller figure -- that ~13,900 lines had never been read by GCC and
# needed wiring up -- was wrong, and the work it implied was already done.
#
# So the probe no longer trusts a list of things to look for. It reads the set of
# source objects the build actually produced and compares it against this file in
# BOTH directions:
#
#   - a file here that was NOT compiled  -> something dropped out of a portable
#     target, or a target stopped building. Silent regression, now loud.
#   - a file compiled that is NOT here   -> the portable surface grew without
#     anyone saying so. Add it deliberately, with a look at whether it belongs.
#
# That symmetry is the point. A one-directional check can only catch shrinkage,
# and it was growth this file's absence hid.
#
# Adding a line is a claim that a non-Windows compiler accepts the file. Do not
# add one to make the probe green -- run the probe and let it tell you.
#
# Windows-only files must NEVER appear here. scripts/probe-portable-linux.sh
# separately asserts that main_d2d.cpp and settings_win32.cpp were not compiled at
# all. settings_app.cpp was in that list until 2026-09-24 and is an entry below now;
# the probe asserts settings.cpp's own independence from app.h instead.
#
# Files under tests/ must never appear here either, even when a non-Windows build
# compiles them. Every name below is read as src/<name> when the probe counts the
# portable share, so a tests/ entry would name a file that does not exist and
# silently spoil the figure. tests/render_api_shared.cpp made that mistake
# available: it is compiled off Windows and does not end in _tests.cpp, so the
# probe reported it UNEXPECTED and adding a line here looked like the fix. The
# actual fix was in the probe's filter, which now keys on the source directory
# instead of guessing from the filename. Those test objects are asserted by name
# further down that script.

# platform_process_qt.cpp -- the non-Windows half of include/platform_process.h, the sixth

# assertion in process_tests is written against the CHILD'S sleep and not against the
# budget for exactly that reason.
platform_process_qt.cpp

# became portable in exchange for ~90 lines that did not.

# zen_mode_qt.cpp IS LISTED, AND THE PARAGRAPH THAT STOOD HERE ARGUED IT SHOULD NOT BE. That

# because the two come apart.

# error -- `MISSING: input.cpp` (listed, compiled by nothing, now in portable_compile_only) and
# `UNEXPECTED: zen_mode_qt.cpp` (compiled, unlisted, now this line). Nothing RUNS either file
# off Windows yet; that is the Qt key router's slice, and it is stated at both sites rather
