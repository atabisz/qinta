# Every src/ file that a non-Windows build compiles, one per line.
#
# WHY THIS FILE EXISTS
#
# scripts/probe-portable-linux.sh used to assert a hand-picked handful of objects
# by name. That is an under-reporting instrument, and it cost a real mistake on
# 2026-09-10: it named five objects, so the portable core looked like ~2,800 lines
# when the Linux build was in fact already compiling 16,252. The conclusion drawn
# from the smaller figure -- that ~13,900 lines had never been read by GCC and
# needed wiring up -- was wrong, and the work it implied was already done.
#
# So the probe no longer trusts a list of things to look for. It reads the set of
# source objects the build actually produced and compares it against this file in
# BOTH directions:
#
#   - a file here that was NOT compiled  -> something dropped out of a portable
#     target, or a target stopped building. Silent regression, now loud.
#   - a file compiled that is NOT here   -> the portable surface grew without
#     anyone saying so. Add it deliberately, with a look at whether it belongs.
#
# That symmetry is the point. A one-directional check can only catch shrinkage,
# and it was growth this file's absence hid.
#
# Adding a line is a claim that a non-Windows compiler accepts the file. Do not
# add one to make the probe green -- run the probe and let it tell you.
#
# Windows-only files must NEVER appear here. scripts/probe-portable-linux.sh
# separately asserts that main_d2d.cpp, settings_app.cpp and settings_win32.cpp
# were not compiled at all.
#
# Files under tests/ must never appear here either, even when a non-Windows build
# compiles them. Every name below is read as src/<name> when the probe counts the
# portable share, so a tests/ entry would name a file that does not exist and
# silently spoil the figure. tests/render_api_shared.cpp made that mistake
# available: it is compiled off Windows and does not end in _tests.cpp, so the
# probe reported it UNEXPECTED and adding a line here looked like the fix. The
# actual fix was in the probe's filter, which now keys on the source directory
# instead of guessing from the filename. Those test objects are asserted by name
# further down that script.

# --- File and folder helpers, compiled AND run off Windows ---------------------
#
# file_utils.cpp. Newly portable, and the thing that made it portable was NOT a
# missing spelling for GetFileTime -- std::filesystem::last_write_time has been
# there all along. It was a REPRESENTATION question, and the answer the comment in
# that file used to give was wrong.
#
# The question: App::lastFileWriteTime is a FILETIME, so are LayoutTab::lastWrite
# and settings.ini's [Recent] timestamps, and the start page decodes those for
# display. The old comment concluded that porting one function therefore meant
# changing the representation at eleven sites, and rejected the cheap alternative
# for a good reason -- packing a POSIX timestamp into a FILETIME's two halves
# satisfies every equality comparison in input.cpp and silently redates the start
# page by 369 years.
#

# fileTimeTicksNow() had been computing genuine 1601-epoch ticks from std::chrono
# on any platform since before that comment was written, so platform::fileWriteTicks
# does the same for a file and all eleven sites are untouched.

# externally reachable functions, none of which had ever been run by a test on
# either platform. Three are string arithmetic that assumes a drive letter, and two

# recognised as a root, so the folder browser offers ".." at the filesystem root --
# rather than changing what the application does inside a portability slice.

# --- The scroll policy, compiled AND RUN off Windows ---------------------------
#
# scroll.cpp. The wheel, arrow-key, page, Home and End arithmetic for the document
# view, and the clamp all five share. Compiled, linked and RUN off Windows by
# qt_entry_tests, and compiled with NO Qt at all by portable_compile_only.
#
# THE SECOND READING IS THE ONE WITH TEETH, and the reason differs from
# paint_document.cpp's. This file exists so that src/input.cpp -- 344 native mentions
# deep and not portable -- can call it instead of keeping its own copy of these
# numbers, and input.cpp will never link Qt. A QWheelEvent or a Qt::KeyboardModifier
# drifting in here would compile fine in both Qt targets and quietly make the shared
# policy unshareable, which is exactly the failure the Qt-free compile catches and the
# Qt-linked test cannot.
#
# WHAT IT DOES NOT CLAIM: that the Windows build uses it. src/input.cpp still holds the
# same numbers at eleven sites and is untouched by this slice, so the two copies exist
# and this file is the one with a test on it. Routing input.cpp here is the deletion
# that makes the claim whole, and it is not done.
scroll.cpp

# --- The scrollbars, cut out of the least portable file in the tree ------------
#
# scrollbar.cpp. The vertical thumb, its find-match ticks and the horizontal thumb: 95
# lines that were inline in src/main_d2d.cpp's paint handler, plus the 8-line visibility
# latch from the same function. Compiled, linked and RUN off Windows by qt_entry_tests,
# and compiled with NO Qt by portable_compile_only.
#
# THIS ONE IS A DELETION, WHICH THE TWO ENTRIES ABOVE ARE NOT. paint_document.cpp and
# scroll.cpp both stand BESIDE a Windows copy -- scroll.cpp says so in as many words, and
# src/input.cpp still holds its eleven duplicate sites. This file has no second copy:
# main_d2d.cpp calls it. So "both stacks draw the same scrollbar" is a claim about the
# PROGRAM here and not just about a file, which is the shape the other two are aiming for.
#
# WHY IT IS NOT A QScrollBar, since that is what the slice was scoped as: tinta's scrollbar
# is a custom-drawn rounded thumb, not a native control, and a Qt widget down the right
# edge would have made the single most visible piece of chrome in the product differ
# between the two builds. Moving the existing code costs the same and produces the same
# pixels. include/scrollbar.h has the full argument.
#
# WHAT IT DOES NOT CLAIM: that the scrollbar is INTERACTIVE off Windows. App's hover and
# drag flags are set by src/input.cpp's mouse handling, so on Qt the thumb draws in its
# resting 6 DIP / 0.3 alpha form and cannot be dragged. The code reads those flags and will
# honour them the moment something sets them -- a missing caller, not a missing half.
scrollbar.cpp

# --- The Qt frontend: the entry point the whole port is aimed at ---------------
#
# These three are a DIFFERENT KIND of entry from everything above. Every other line
# in this file is a file that used to need Windows and stopped; these were written
# for the Qt stack and have never had a Windows half at all. They are the beginning
# of what replaces src/main_d2d.cpp rather than a portability repair.
#
# LINKED AND RUN, not compile-only: tests/qt_entry_tests.cpp constructs the same
# QtAppWindow src/main_qt.cpp runs, grabs it, and reads the pixels back. It is the
# first test on this tree to paint a tinta WINDOW -- every other drawing assertion
# paints into a bitmap and involves no widget, no paint event and none of App's seam
# storage.
#
# WHAT THEY COST: nothing elsewhere. The link closure was MEASURED before these were
# written -- a scratch probe linked a Qt main() against an archive of all 39 portable
# objects and read the link map -- and it came back at six existing files, all
# already listed above. No file had to be split, no seam had to be added, and no
# native call had to be routed. That is the first slice in this port for which that
# is true, and it is what the header work above bought.
#
# THEY RENDER A DOCUMENT AS OF 2026-09-16, and the sentence that stood here said they
# did not. It is worth reading what it said, because it was corrected twice and each
# correction shrank the gap rather than closing it: first "because src/render.cpp does not
# compile off Windows", then "a LINK reason, not a compile one: qinta is six symbols
# short, all of them in src/math_render.cpp". Both premises were true when written. The
# six symbols are now src/math_stub.cpp, so the LINK is closed and the MATHS is not --
# which is the third shape of the same gap and is recorded under render.cpp above rather
# than allowed to disappear into a green run.
#
# What closed it in the part that matters: qt_window.cpp calls layoutDocument and
# paintDocumentLayout, and it reports which branch it took through
# QtAppWindow::documentPainted(). That predicate exists because both branches draw dark
# text on the theme background, so a pixel test with no way to tell them apart would
# report the PLACEHOLDER as a rendered document.
# That list is measured too: 23 of the 24 src/ files outside
# this manifest fail a syntax-only non-Windows compile, on 12 distinct first causes.
# README.md carries it. src/settings_app.cpp is the 24th -- it compiles off Windows
# already, and the probe asserts it is NOT built, which is now a deliberate exclusion
# rather than a Windows dependency.
qt_init.cpp
qt_window.cpp
main_qt.cpp
